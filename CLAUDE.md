# CLAUDE.md

Guidance for Claude Code when working in this repository.

## What this is

C3 bindings for [ufbx](https://github.com/ufbx/ufbx) (single-file FBX loader, MIT or Unlicense),
packaged as a C3 library (`.c3l`), not a standalone program.

- `manifest.json` provides the `ufbx` package for the `ufbx` module. `"sources": [ "src/**" ]`
  replaces the default scan of the package root. `"c-sources": [ "csrc/ufbx.c" ]` compiles the
  ufbx implementation with the consumer's C compiler on every target; there is no native archive.
- `src/ufbx.c3i`, `src/layout.c3`, `scripts/abi-sizes.txt` and `scripts/abi-offsets.txt` are
  generated by `scripts/gen_bindings.py` from upstream's bindgen IR and never edited by hand.
  Change the generator, then regenerate.
- `src/ufbx.c3` is the hand-written idiomatic layer: the `faultdef`, `error_fault`, and the
  wrappers consumers call.
- `vendor/ufbx/` is upstream as a git submodule, pinned to a release tag. Read the real declaration
  in `vendor/ufbx/ufbx.h` before changing a wrapper; a wrong field or parameter type is a silent
  cross-ABI memory bug.
- `test/` is a standalone consumer project. `test/libs/ufbx.c3l` is a symlink to the repository
  root because c3c resolves a dependency as `<search-path>/<name>.c3l`.

## Authoring rules

- Invoke the `c3-expert`, `c3-style` and `c3-bindings` skills before writing, editing or
  reviewing any C3 or diagnosing a c3c error. C3 is 0.8.3 here and pre-1.0.
- Do not run `c3fmt`. Hand-format: K&R braces, four spaces, one fault per `faultdef` line.
- Docstrings on every wrapper: one summary line, `@param` for pointers and any parameter its name
  does not explain, `@return?` listing every fault. The generated raw layer carries none.
- No development vocabulary in code: no ticket references, plan steps or milestone names.

## Binding conventions

- The `ufbx_` prefix is the module name, never part of an identifier: `ufbx::load_file`, not
  `ufbx::ufbx_load_file`. Functions `snake_case`, types `PascalCase`, constants and enum values
  `SCREAMING_SNAKE_CASE`. No `@builtin`.
- Enum values strip the longest common prefix of their enum's values; a remainder starting with a
  digit keeps the last prefix word (`FORMAT_16MM_THEATRICAL`). Auxiliary enum aliases become
  constants of the enum type.
- `ufbx_real` stays `double`; do not define `UFBX_REAL_IS_FLOAT`.
- Consumers that also import `std::math` or their own `Vec3`, `Transform`, `Node`, ... must qualify
  one side: C3 rejects an unqualified name defined in two imported modules.

## Verification

```sh
python3 scripts/gen_bindings.py --check
scripts/probe-layout.sh
c3c compile-only --no-obj src/*.c3i src/*.c3 && rm -rf obj
cd test && c3c test
```
